## 2. Per-round protocol (do every fire — ship, don't just report)

1. **Inspect** current `/admin` UX + code; read `MEMORY.md` + `_extra-feature-modules-50.md` + this file.
2. **De-dup check** (mandatory): does the candidate already exist (catalog/modules/flags/snapshots)? If yes → extend/polish, never rebuild.
3. **Pick** the highest-priority unmet, *reachable*, *safe* item (P0 first).
4. **Test first** — write/update the Playwright (or Karma unit) test describing expected behavior; watch it fail where behavior is broken.
5. **Implement** the smallest correct slice.
6. **Verify** — re-run the test green; typecheck; build; manually reason through the route.
7. **Commit to `main`** (additive/new files preferred when worktrees are busy). Deploy frontend to R2 only if no deploy is mid-flight; else commit and let the cycle deploy.
8. **Summarize** the exact change + what's next. Then continue to the next item.
- At least ONE **visible cyan/black UX improvement per round** unless the round is exclusively fixing a blocking test or a P0 correctness bug.

## 4c. Reliability recipe — error-state gating (a fetch error must never masquerade as empty/blank/default)
- **Gap-finder:** scan section components for `.get<`/`.subscribe` fetch count vs presence of an `error`/`loadError` signal + render branch. A section that fetches but, on a non-404 error, renders its EMPTY state, a BLANK area, or (worst) a DEFAULT-valued EDITABLE form = a silent failure (and on save/publish surfaces, a data-loss risk — the operator can overwrite real data that merely failed to load).
- **Recipe (3× applied: logs 1ae8d11c, trust-center 48e0d084, enterprise da7e2d17):** add `loadError = signal<string|null>(null)`; set null at fetch start + on success; on non-404 error set a message (404 keeps its honest flag-disabled/empty card — that's genuine, not a masquerade); template: a persistent cyan/black error card `@if (loadError() && !loading())` with a **Retry** button (`role=alert`, `data-testid=<section>-load-error`/`-retry`), AND gate the results/editor with `&& !loadError()` so the failed fetch can't present a usable-looking state. Add a loading skeleton `@if (searching/loading() && no rows)` where the area would otherwise be blank during load.
- **Verify:** spec (overrideComponent-isolated) asserting success-clears / non-404-sets-persistent-error+toasts / 404-disabled-card-no-error / retry-clears; `ng build` AOT-verifies the real template; commit fast + snapshot-verify.
- **✅ SWEEP COMPLETE (5 fixes):** logs (1ae8d11c) · trust-center (48e0d084) · enterprise (da7e2d17) · inbox (3c95a086) · stripe-app-status (89d48e0b). `features-hub` verified OK (surfaces errors inline by design). The error-masquerades-as-empty/blank anti-pattern is closed across every audited fetch-heavy admin section, each with a regression spec. NEW fetch-heavy sections must apply this recipe from day one; a periodic re-scan (fetch count vs error-signal) catches regressions.

## 4b. Dead-control reachability lesson (P0 — verify the error handler, not just the route)
- **"Worker route missing" ≠ "scary dead button."** Before treating a frontend→missing-route call as a P0 dead control, READ its error handler + check button reachability: (a) silent handlers (`error: () => this.x.set(null)`) just leave a feature non-functional — no scary toast (e.g. social `fetchOg`); (b) gated buttons can be unreachable in the degraded state (sessions revoke is `@if(!s.current)` + `@if(length>1)`, and the GET falls back to ONE synthetic current row → neither renders). Both are lower-priority than a button that fires a misleading toast on click. The genuine P0 = a control that, on click, error-toasts against a 404 (e.g. social `import-rss` "Could not parse feed"). Fix order: wire-it > honest-message > graceful-disable. Reference: f050805d wired `import-rss` preview (`parseRssFeed` + SSRF route); 5693d0b5 wired `og-preview` (`parseOgTags` + SSRF route) PLUS a VISIBLE fallback link card (`.og-card--fallback`: hostname+url+"Preview unavailable" when OG absent → pasting a link is never a silent no-op). Pattern worth reusing: **pure parser (Jest) + SSRF-guarded fetch route (ships on push) + a frontend graceful-fallback (R2-visible now)** turns a silent/dead feature into a working-or-gracefully-degraded one in ONE round. See [[dead-admin-mutation-actions]]. **RSS feature now COMPLETE end-to-end (5ec2c64f + 273d1519): Preview (parseRssFeed) → Import N as drafts (buildRssDraftRows → pulse_posts drafts) OR Copy links (clipboard).** The schedule path's 501 is gone — non-preview import-rss now creates editable drafts.
