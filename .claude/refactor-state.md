## Lessons (hard-won)
- **`db.batch([stmt,stmt])`** is THE atomic-multi-write pattern (implicit txn, rejects+rolls-back on any failure). Convention ref: `credits.ts`. Test it by giving the D1 mock a capturing `prepare`+`batch` jest.fn (+ `mockRejectedValueOnce` for the atomicity/rollback assertion).
- When a source change alters a function's D1 access pattern (e.g. dbUpdate→batch), grep **ALL** `*.test.ts` calling it + update every mock; verify each **STANDALONE** — co-scheduled `--runInBand` runs mask which suite actually fails (iter-19 regression misdiagnosed as a "flake", caught iter 22).
- **Config-tested ≠ behavior-tested (iter 42 DeepSeek routing).** A green test suite can hide a live bug when it tests the CONFIG (`chooseProviderForTier` returns 'deepseek', the base-URL CONSTANT is 'api.deepseek.com') but never the actual ROUTING (does a call ACTUALLY hit api.deepseek.com?). The DeepSeek tier's config was 100% correct + tested, yet every call went to OpenAI's URL because the dispatch dropped the provider. **When auditing a routing/dispatch/selection service, don't trust "config resolves to X" tests — add a BEHAVIORAL test that mocks the network seam (`gatewayFetch`) and asserts the request went to X.** (Sibling of the [[verify-against-source-of-truth]] render-vs-endpoint blind spot: selection-vs-dispatch.)
- **Re-pathing an FE call must update its Karma SPEC assertions too, not just call sites (iter 38 caught iter 32).** iter 32 re-pathed the integrations DELETE `/integrations/` → `/integration-providers/` (code + 2 call sites) but left `site-detail.component.spec.ts:389` asserting the old path. It stayed RED from iter 32→38 because the FULL frontend Karma suite wasn't run to completion (state claimed "Karma 1592/1592 iter 4" — stale). **Lesson: (a) when touching any FE `/api` path, grep the SPECS for the old string + update assertions; (b) a frontend change's verification MUST run the WHOLE `npm run test:ci` (1610 tests, ~2min) — a scoped run hides stale specs elsewhere. Adding ANY spec = run the full suite (gotcha #9 order-flake + surfaces long-hidden reds).**
- **Angular control-flow migration = official schematic, not hand-edits (iter 37).** `ng g @angular/core:control-flow --path=<dir> --interactive=false` migrates `*ngIf`/`*ngFor`/`*ngSwitch` → `@if`/`@for`/`@switch` AND is SMART: it removes the now-unused `CommonModule` import + swaps in the SPECIFIC pipe (`CurrencyPipe`) a template still needs — the DELETE pass is done for you. `--path` scopes it (avoid the BLOCKED admin-shell). Dry-run first to confirm scope. After: the only residual `*ngIf`/`*ngFor` are STALE PROSE COMMENTS (perl `s/\*ngIf/@if/g` cleans them — templates are already migrated so it only hits comments). Verify via `ng build` (AOT compiles EVERY template even tree-shaken ones → a broken migration or wrongly-dropped CommonModule = loud compile error) since site-kit has 0 Karma specs. ⚠️ `\| number` grep false-positives on TS union types (`x: string \| number`) — read context.
- **"Saturation" is premature while whole SUBSYSTEMS remain unexamined (iter 53).** iters 51-52 declared "terminal saturation" — but that was measured against the surfaces I'd ALREADY audited (services/routes/dead-code). iter 53 pivoted to a genuinely-unexamined subsystem, `build_validators.ts` (the product-core quality gates, LIVE, never behaviorally audited), and immediately found a real bug (metaDescLength apostrophe truncation) firing on the flagship test business. **Lesson: when a loop feels saturated, the saturation is usually LOCAL to the audited surfaces — PIVOT to a genuinely-unexamined subsystem (grep for services/routes with 0 prior refactor-state mentions) BEFORE concluding global saturation.** Unexamined-but-live product-core code (validators, build pipeline, middleware chain) is where the next real bug hides. Do NOT emit "saturated, honest checkpoint" until every LIVE subsystem has ≥1 behavioral audit recorded.
- **knip's "unused files" misses self-referential module+tests islands — BUT the "0-production-caller" sweep is a false-positive MINEFIELD, not a bulk deletion tool (iters 50-51).** iter 50 found `confidence.ts` (906-line `transformToV3` v3-research pipeline, orphaned by the container-arch refactor) that knip missed because its 52K of tests count as "consumers." Real win: 2224 lines deleted. **BUT iter 51 ran the 0-caller sweep at SCALE and it flagged ~220 services — including `turnstile` (definitely live: better-auth/forms/listmonk import it), i.e. a broken-grep false positive — AND even the sharper "0-caller + has-test" variant false-positived `plan_migration` (imported by `plan_migration_log`).** The repo has a LARGE INTENTIONAL built-ahead surface (~220 uncalled services from the "40-list build wave" + platform fan-outs per [[dead-code-scan-baseline]]). **So: `0 production callers` alone is NOT a delete signal — it's dominated by built-ahead.** A module is safely-deletable ONLY with confidence.ts's FULL signature: (1) 0 non-test importers across `src/`+`libs/`, (2) a DEDICATED test file is the sole consumer, AND (3) **`git log -S` proves it served an architecture that was EXPLICITLY REPLACED** (built-BEHIND), not parked-for-future. iter 51's 4 narrowed candidates (`outbox_processor`=built-ahead "spine", `plan_migration`=has-caller, `theme_polarity`=documented "Logo Luminance" feature, `voice_twiml`=active voice area) ALL failed condition (3) → KEPT. ⚠️ Do NOT build a `check-orphaned-modules.mjs` DELETION gate off this — per [[validator-precision-discipline]] it would be a false-positive machine. confidence.ts was a rare clearly-replaced-arch case, NOT a generalizable vein.
- **A source-grep "moot / dead / safe-to-delete" verdict MUST be prod-verified before any route/handler deletion (iter 47 near-miss).** iter 33 concluded (from reading code) that the 2nd `GET /` handler was moot and instructed a future session to DELETE it. iter 47 prod-curled the actual hosts first and found it serves FIVE live 200 landing pages — the delete would have 404'd llm/analytics/logs/webhooks/links. The grep-analysis conflated two similarly-named hosts (`llm.projectsites.dev` vs `llm.megabyte.space`) and assumed container-interception that didn't exist. **Before deleting ANY route/handler a prior analysis called dead: curl every host/path it could serve, in prod, and confirm something ELSE already serves them.** A stale "safe to delete" note is worse than no note — it launders a guess as a verified fact. Sibling of [[grep-closed-not-resolved-redirect-hidden-request]] + [[verify-against-source-of-truth]]. When correcting such a note, fix it IN the durable artifact (here: the detector allowlist comment) so the bad guidance can't mislead again.
- **Hand-rolled duplicate maps drift silently from their canonical (iter 44).** The same lookup table (a MIME map, a config map, a provider list) copied inline at N call-sites WILL drift — one copy gains an entry the others lack, and the gap is a silent wrong-output bug (a `.webp` served as `octet-stream`, never an error). iter 44 found THREE content-type maps, all divergent from `getContentType`. **Fix = export the ONE canonical, route every call-site through it, delete the copies.** When you see a second inline copy of a lookup that already exists as a function, that's the bug — collapse to the SSOT, don't patch the copy. Sibling of [[aggregate-endpoint-drifts-from-per-item-truth]] (rollup re-implements per-item probe → diverges) — same class, config-map form. Grep for the class (`Record<string, string>` inline maps, repeated key literals like `'image/png'`) before claiming a serving path converged.
- **Grep-close the CLASS before claiming a sweep (iter 35).** Fixing the instance in front of you under-delivers when the same bug shape lives in sibling files. iter 35 started with 2 instances found by local reading (site-generation inline + cron); the class-grep (`FROM memberships`/`JOIN memberships` minus `deleted_at`, then READ each multi-line context) surfaced **3 MORE** in separate service files (`notify_site_built`, `notify`, `build_limits`) that the initial reading never touched. The tree-wide grep + per-hit context-read is what converts "fixed a bug" into "swept the class." ⚠️ Single-line grep is only a CANDIDATE list — multi-line queries carry `deleted_at IS NULL` on the NEXT line (`weekly_digest`/`auth_org`/`wallet` were false-positive "misses"); always read the surrounding lines before judging.
